## 顺手做了一次「减抄写面」的重构

`opCreateManual` 原先在 `undo.js`，但它依赖 `canSetParentLoose`，而后者连着
`setCanSetParent` 的注入接线。客户端不能 import 相对模块 ⇒ 要用它就得抄
**函数 + 私有依赖 + 注入接线**三样，三处都可能分叉。

迁到 `src/overlay/manual.js`（零依赖纯函数模块，只 import `index.js` 的 `canSetParent`）后：
- `undo.js` 重新导出它，**不存在两份实现**；
- 客户端只需**逐字复制一个函数**。
防漂移断言从 3 个函数扩到 **8 个**（新增 opCreateManual / canSetParentLoose / isDescendant / canSetParent）。

## 真机抓到的一个真 bug：TDZ 自遮蔽

```
ReferenceError: Cannot access 'canSetParent' before initialization
    at opCreateManual
```

为了「逐字一致」我把客户端的 `canSetParentCanonical` 对齐成了本地那份 `canSetParent`，
于是函数体里出现：

```js
const canSetParent = deps.canSetParent || canSetParent   // ← 右边读的是还没初始化的自己
```

**同作用域的 `const` 遮蔽了外层函数** ⇒ TDZ 报错。症状是点「＋」**毫无反应**，
只有 console 里一条异常 —— 面板不报错、不落盘、静默失败。

为什么离线断言全绿也看不出来：宿主那份用的是**不同名**的 `canSetParentCanonical`，
所以只有客户端副本会炸；而离线套件跑的是宿主那份。
**「对齐命名」这个动作本身制造了 bug** —— 这是逐字复制策略的意外代价。

修法：默认值落在**不同名**常量 `canSetParentFn` 上（两处都改，保持逐字一致）。

新增两条断言 + 变异测试：
- 机械判据 `const X = deps.canSetParent || X`（自遮蔽形状）**必须不出现**，两侧都查
- 变异（改回自遮蔽写法）⇒ **2 条红**（TDZ 断言 + 漂移断言），确认能咬住
