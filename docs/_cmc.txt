## 做了什么

双击链行 → 变输入框；`Enter` 提交、`Esc` 取消、失焦提交；`F2` 也能进（键盘入口）。
提交走 `opAnnotate`（`undo.js` 的**逐字副本**）→ `saveAuthority` → 宿主 `save` 落盘。

因为现在有两种意图（设焦点、写注解），`saveAuthority` 的 409 重放扩成认两种：
注解重放是**在权威 doc 上重算** `opAnnotate`，而不是把旧快照拍上去 ——
后者会抹掉刚落链的节点。

## 接线时踩到的三个坑（都写了注释 + 断言）

1. **React 的合成 `onDblClick` 在 DSH 的 Web shell 里不响应**（真机实测）。
   原生 `dblclick` 确实冒泡到了 React 根容器 `#root`（`getEventListeners(#root).dblclick`
   有、自挂的捕获监听也收到），而**同一元素的 `onClick` 完全正常**；
   直接调 `props.onDblClick()` 也是好的 ⇒ 问题在派发层。
   **改法**：用已验证可用的 `onClick` 自己判「两次快速点击」（450ms），
   保留 `onDblClick` 与 `F2` 作附加入口。断言明确要求**不能只依赖 onDblClick**。
2. **`<input>` 不能嵌在 `<button>` 里**（非法 HTML ⇒ 浏览器重排 DOM ⇒
   `autoFocus`/`blur` 错乱）。链行主元素从 `button` 改成 `div` + 手写
   `role`/`tabIndex`/键盘处理。
3. **按 Enter 提交后输入框卸载会触发 `onBlur`**，那一刻 `annotating` 的闭包还是旧值
   ⇒ 会保存两次。用 `useRef` 做同步闸门（ref 写入同步，同一轮事件里立刻可见）。

## 顺带修掉一个**验收工具**的 bug

`cdp-panel.mjs` 的 `ensurePanelOpen` 只要看到面板根节点就返回 `already-mounted` ——
但面板是**按会话**挂载的，「已挂载」不等于「挂对了会话」。于是整轮验收会在错的会话上跑
（实际踩到：验注解时打开的是测试会话，面板里只有 1 行，三条断言全红）。
现在先比对会话，不一致就切过去。
