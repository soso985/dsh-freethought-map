# FreeThought Map · DSH 插件版 · 产品与技术规格

> 与 `00-AI接力-先读.md`、`02-实施计划.md` 配套。  
> 独立站方案（ChatPanel、`MapDoc.messages` 双写、整图 localStorage 快照当聊天真源）**作废**。

---

## 1. 定位

DSH 负责聊。本插件是当前会话的外置工作记忆（链→网）。  
不是独立站、不是 talk-map、不是 mindmap-chat、不是一键成树、不是第二套 Agent。

---

## 2. 概念

| 词 | 定义 |
| --- | --- |
| **结算回合** | 进入会话 canonical 时间线的：一条用户消息，或一次 **成功的** assistant 文本结算。不含 stream 帧、不含失败 attempt、不含纯工具过程 |
| **sourceRef** | 投影绑定：`{ kind: 'user-message' \| 'assistant-settlement', eventId: string }`。`eventId` 必须是该条结算的**稳定事件 id**，不是 turn 容器 id |
| **投影节点** | `kind:'turn'`，有且仅有一个 sourceRef |
| **手建节点** | `kind:'manual'`，无 sourceRef |
| **注解** | overlay 上可选的 `title`/`body` |
| **摘除** | sourceRef 进入 hidden 集；会话原文仍在 |
| **overlay** | parentId、freeLinks、position、注解、hidden、focus、手建节点、几何 |
| **选中 selectedIds** | **视图状态，不进 overlay**（主人拍板 2026-09-27）。只活在客户端内存里，刷新即丢；**不落盘、不同步** |
| **焦点 focusId** | 下一句默认父节点；点空白**不清空**；与 selectedIds **分离**。**这个进 overlay**（它影响投影与注入） |
| **发送快照** | 用户点官方发送时：`parentIdAtSend` + `newPinkLinksAtSend` + `focusIdAtSend` |

## 3. 红线

1. 禁止一次生成长整图（无按钮、无写结构工具、无「整理成树」prompt 入口）。  
2. 模型只读图。  
3. 拉线不自动 `followup`。  
4. 拖拽只改 position。粉线不参与层级。  
5. 不引入全图唯一根。断开不自动重挂。  
6. 第一版不改写、不删除 DSH 历史。  
7. 不 fork 官方包。不把全局 CSS/快捷键打到宿主。  
8. 工具里的 sessionId 必须来自执行上下文。

## 5. 界面与隔离

- 插件 UI **必须**挂在自己的根节点上（例如 `#freethought-map-root`），主题用根上 `data-theme`，**禁止**写宿主 `<html>`。  
- CSS 限定在根下（CSS modules / 前缀 / shadow）。**禁止**全局 `body`、`button`、`:root` 改官方聊天。  
- 快捷键与方向键：**仅当事件目标在插件根内**才处理。官方输入框聚焦时不得拦截 Enter。禁止长期 `window` 全局 listener 不检查 target。
  - `Ctrl+Z` / `Ctrl+Shift+Z`（撤销/重做）同样**仅当焦点在插件根内**才处理（主人拍板 2026-09-27）。
    理由：官方 composer 自己也有撤销；全局拦截会破坏宿主体验。已实测的键盘隔离机制（卡 1 / D1-4）直接复用。
- `selectedIds` 与 `focusId` 分开存。单击选中可同时设 focus；**单选/多选都只改 selectedIds，不动 focusId**。
  - **`selectedIds` 是视图状态，不进 overlay**（主人拍板 2026-09-27）：只活在客户端内存，刷新即丢。
    它**不参与**落盘、不参与导入导出、不参与发送快照。`focusId` 反之 —— 它影响投影与注入，**必须**进 overlay。
  - **第一版不做多选**（主人拍板 2026-09-27）：`selectedIds` 长度恒为 0 或 1，不实现框选。
    保留"可多选"的类型形状以便日后扩展，但 UI 不做。
- 收对话后：窄条底部仍可输入（若卡 1 探针做不到，记入 HOST.md 并采用抽屉里保留完整官方 composer）。

双向定位 **以卡 1 探针结果为准**（见 §8）。规格要求：

- 新投影落地：选中该节点，轻推视口，不整图 fit。  
- 单击投影 → 滚到官方对应气泡。  
- 单击官方气泡 → 选中节点并设 focusId。  
- 单击手建节点 → 只设 focus，官方不跳。  
- 点空白：不清 focusId。

v0.1 可复用：双连线绘制、parent 防环、删点后子节点上提、dropPosition、节点外观。  
**禁止搬入：** `AIPanel`、`aiStore`、`services/ai.ts`、整份 `mapStore`+localStorage 单文档、`App.tsx` 壳、全局 `index.css` 的 body/button。

## 6. Overlay 与身份

### 6.1 真源

- 会话 canonical 时间线：DSH（只读）。  
- 图结构：overlay。Host 写入权威。键：`sessionId`。

### 6.2 类型

```ts
type SourceRef =
  | { kind: 'user-message'; eventId: string }
  | { kind: 'assistant-settlement'; eventId: string };

type OverlayDoc = {
  version: 1;
  sessionId: string;
  rev: number;                 // 单调递增，乐观并发
  nodes: Record<ID, OverlayNode>;
  freeLinks: { id: ID; a: ID; b: ID }[];
  focusId: ID | null;
  hidden: SourceRef[];         // 摘除的投影（按 sourceRef 不是按 node.id）
  updatedAt: number;
};

type OverlayNode = {
  id: ID;                      // 插件 UUID，一旦创建稳定
  kind: 'turn' | 'manual';
  sourceRef?: SourceRef;       // turn 必有；manual 禁止有
  parentId: ID | null;
  title?: string | null;       // 见 §10：undefined=未注解；""=清空
  body?: string | null;
  position: { x: number; y: number };
  width?: number;
  height?: number;
  tags?: string[];             // 保留，第一版 UI 可先不暴露
  collapsed?: boolean;
  locked?: boolean;
  color?: string;
  shape?: string;
};
```

**禁止**把 eventId 与 turnId 混用。一个内核 turn 可含多事件；**一个投影节点只对应一种 SourceRef**。  
同一 overlay 内 `sourceRef` 唯一。重复事件、重连重放：已有映射则 **no-op**（不新建、不改 parentId/position/注解）。

### 6.3 事件 → 节点

| 内核现象 | 图 |
| --- | --- |
| 用户消息进入 canonical | 若该 eventId 未 hidden 且无节点 → 建 turn 节点 |
| assistant **成功文本结算** | 同上，kind assistant-settlement |
| assistant 失败 attempt / 中止 | **不建节点** |
| stream 中间帧、工具调用过程 | **不建节点** |
| 官方重新生成且 canonical **替换** 旧结算 | 旧 sourceRef 若不再出现在 canonical：节点视为孤儿投影，**自动摘除**（写入 hidden 或删除 turn 节点但保留 manual 子上提）。不得留给用户一条指向幽灵事件的点 |
| 官方重新生成且 **追加** 新结算、旧的仍在 | 新旧各一节点；新节点父=其用户消息节点 |
| 分页「加载更早」 | 只对**新进入已加载窗口**的结算补链（§6.5） |

### 6.4 落链与焦点（时序）

**发送瞬间（客户端，官方发送钩子或等价）：**

1. 生成 `sendNonce`。  
2. 快照 `parentIdAtSend = focusId`（节点必须仍存在，否则 null=新顶层链）。  
3. 快照 `newPinkLinksAtSend` = 自上一已消费发送以来、尚未消费的新粉线 id 列表（见 §10.3）。  
4. 把快照与即将发出的用户文本关联。排队多条消息时 **每条自己的快照**，禁止等事件到达再读「当时 focus」。

**用户结算事件到达：**

1. 去重 sourceRef。  
2. `parentId` = 该条 `parentIdAtSend`（对得上 nonce/文本/官方 client tag 则用；对不上则退化为「时间线上前一条未隐藏 turn」，**禁止**用此刻 live focusId）。  
3. 显示标题派生自原文截断 24 字，**不写入** title 字段。  
4. `focusId = 新用户节点`。  
5. 此步是 **session-sync**，不进用户撤销栈。

**Assistant 成功结算到达：**

1. 去重。  
2. `parentId` = 对应的用户节点（用会话配对；找不到则用该 assistant 时间线之前最近 user 投影）。  
3. **抢焦点规则：** 仅当 `focusId === 该用户节点 id`（用户还停在这条提问上）时，`focusId = 新 AI 节点`。若等待期间用户已点了别的节点，**不改 focusId**，AI 节点仍挂到该用户节点下。  
4. session-sync，不进撤销栈。

目标链：`U1→A1→U2→A2`（在用户未中途改焦点时）。  
用户在 A1 等待时点了别的节点 F，则：A1 仍是 U1 的子；U2 的父是 F（发送快照）。

### 6.5 历史补链

- **禁止**用当前 live focusId 给历史节点当父。  
- 打开会话 / 重连：先加载 overlay（含 hidden），再按 canonical **从旧到新** 扫描已加载窗口。  
- 对每个结算：若 hidden 则跳过；若已有 sourceRef 则跳过（保留用户 parentId/位置/注解）；若缺失则新建，`parentId = 时间线上前一个已存在且未隐藏的 turn 节点`（仅此缺省；一旦写过 overlay.parentId 永不用补链覆盖）。  
- 「最近 100 轮」：**100 个用户消息结算**（不是 100 个 event，也不是 100 个 assistant）。更早的：官方尚未加载则不投影；官方「加载更早」进入窗口后再按上款补。提供「重建投影」：对**当前已加载窗口**跑同一算法，仍不覆盖已有结构、不复活 hidden。  
- 补链是 session-sync：不进撤销栈。刷新后再补会再次保证 canonical 与 overlay 对齐（hidden 除外）。

### 6.6 摘除后子节点（唯一规则）

删除或摘除节点 X：

- X 的所有子节点（turn 与 manual）`parentId ← X.parentId`（上提，可因此变成顶层）。  
- 与 X 相连的粉线删除。  
- 若 X 是 turn：`hidden` 加入其 sourceRef；节点记录可删掉或保留 stub，推荐 **删除 node 记录 + hidden 留 sourceRef**，补链才不会立刻建回。  
- 若 X 是 focusId：`focusId ← X.parentId`（可为 null）。  
- 若 X 在 selectedIds：移出。  
上提后若成环（不应发生）：拒绝此次删除并提示。防环算法复用 v0.1。

## 7. 投影与撤销（卡 3 前必须实现）

| 动作 | 进 overlay 用户历史？ | Ctrl+Z |
| --- | --- | --- |
| 自动投影新建 turn | 否 | 不能撤掉该节点；要去掉用摘除 |
| 补链 / 重建投影 | 否 | 同上 |
| 官方替换导致自动摘除幽灵 | 否 | 不能靠撤销恢复幽灵 |
| 拖动、改父、粉线、注解、摘除、手建、改几何 | **是** | 只逆转该用户操作 |
| 拖动 **期间** 到达的 AI 投影 | 否 | 结束拖动提交的是位置；撤销拖动 **不得** 删掉该 AI 节点 |

实现约束：

- **禁止** v0.1 那种「beginEdit 整份 doc 快照含即将到来的投影」。拖动只记录被拖节点的 position 前后。  
- 用户历史是 **操作日志或结构化 patch**，回放 apply 到「当前 overlay」（当前可含更新的投影）。  
- 历史 **按 sessionId 隔离**；切会话换栈。  
- 栈深 50 步用户操作。  
- 「摘除」可撤销（unhide + 恢复节点与子 parent——撤销日志须足够）。  
- 刷新：用户历史可丢（第一版允许只活在内存），overlay 以 Host 为准；因此刷新后不能 Ctrl+Z 跨刷新。须在帮助里写明。

## 9. 持久化协议（Host 权威）

### 9.0 `rev` 的语义（2026-09-27 钉死，P0）

**`rev` = 该会话权威 overlay 的修订号。任何一次「权威 doc 内容发生变化」的写入都必须 `rev++`。**

具体地：

| 写入来源 | 是否改变权威内容 | 是否必须 `rev++` |
| --- | --- | --- |
| 用户保存（`save`，改动结构/位置/注解/焦点） | 是 | **是** |
| **自动投影**（`session/event` → 新建 turn 节点） | 是 | **是**（← 原先漏了，2026-09-27 修） |
| 重建投影补链（新建了节点） | 是 | **是** |
| 幽灵清理 / 摘除 | 是 | **是** |
| 投影去重命中（no-op，内容没变） | 否 | 否（不空转递增） |
| `importDoc` 合并 | 是 | **是** |

**为什么这条必须成立**：`save` 的并发保护只有一条判据 —— `baseRev === 当前 rev` 才写，否则 409。
如果自动投影改了内容却**不**递增 `rev`，那么拿着旧 doc 的客户端提交时 `baseRev` 仍然"相等"，
它会**整份替换**权威（`applySave` 是全量替换语义），于是**把刚落链的节点覆盖掉**。

> 这条不是理论风险：2026-09-27 真机上观察到 `rev=0` 却有 3 个投影节点（父链完整），
> 即「投影写盘但 rev 不动」。同一时刻面板的 `baseRev` 也是 0 —— 保存会通过校验并覆盖。

**由此推出的两条配套约束**：

- **`applySave` 是全量替换** ⇒ 只有在**客户端持有的就是最新 rev** 时才允许替换。
  这也是为什么「任何内容变化都递增 rev」是前提，而不是可选项。
- **客户端在 409 之后必须能重放自己的改动**，不能只重载了事
  （重载 = 用户那次点击白做）。做法：冲突时把「本次意图的那一个字段」重新套用到权威 doc 上再提交一次。
  规格原先只写「不得用本地覆盖，应合并或提示」，「合并」这一半现在必须真正实现。

---

1. **Host 是写入权威。** overlay 文件/storage-domain 只由 host 写。浏览器内存是缓存。  
2. **加载：** 切到会话 → client 请求 `load(sessionId)` → 以返回的 `{ doc, rev }` 替换本地。在途的旧 session 响应全部丢弃（generation 计数）。  
3. **保存：** client 发 `save(sessionId, doc, baseRev)`。Host：`baseRev === 当前 rev` 才写入并 `rev++`；否则 **409 过期**，返回权威 doc，client **不得**用本地覆盖，应合并或提示「已从宿主重载」。  
4. **拖动：** 拖中不 save；endEdit 一次 save。投影 sync 由 host 在收到 session/event 时改权威 overlay，再推 client（或 client 事件后 save 失败则 409 重载）。推荐：**投影由 host 听 session/event 直接改权威**，client 只推用户操作。若做不到（事件只在 client）：client 带 baseRev 提交「applyProjection」命令，仍走同一 rev。  
5. **切会话：** 增加 generation；忽略过期回调；未完成 save 若 session 已切走，完成后发现 sessionId 不符则丢弃回包，不写进新会话缓存。  
6. **断线重连：** 重连后 `load` 再补链，不先用本地旧缓存覆盖 host。  
7. **保存失败：** 插件内可见提示（不是 console only），用户可重试。不得假装已保存。  
8. **只读工具：** `sessionId` = 该次 tool execution 所属 agent/session。即使用户浏览器看着另一个会话，也不得读错图。无执行上下文则拒绝调用。

## 10. 注解、派生标题、粉线快照、工具限额

### 10.1 注解

- 字段 **缺失 / undefined**：显示用 DSH 原文（title 派生 = 原文首行截断 24 字，不写回 overlay）。  
- 字段 **""（空字符串）**：用户主动清空，显示空，不再回退原文。  
- 字段 **非空**：显示注解。  
- 原文始终可从 session 读；UI 可「查看原文」。

### 10.2 几何

保留 `width`/`height`/`tags`/`shape`/`color`/`collapsed`/`locked`。第一版 UI 可不做标签编辑，但 overlay 与 JSON 往返不得丢字段。

### 10.3 「本轮新粉线」

- 维护 `pendingLinkIds`：拉线成功加入；用户删线则移出（若尚未消费）。  
- **发送快照**复制当时 `pendingLinkIds` 到该次 send。  
- **消费：** 该用户消息被 canonical 接受后，从 pending 去掉快照里仍存在的那些 id。  
- **官方重试同一发送：** 复用**同一次**快照，不重新采样。  
- **发送后、消费前删线：** 仍按快照注入（用户发送时的意图）。  
- 注入文案标为用户数据，例如：`[用户图数据] 用户将《A》与《B》建立自由联想`。

### 10.4 短上下文与工具

均标记 `[用户图数据]`。上限：

| 出口 | 上限 |
| --- | --- |
| 焦点正文摘要 | 500 字 |
| 粉线注入 | 最多 20 条/次发送 |
| map_overview 链上节点 | 最近 30 个标题，每标题 80 字 |
| map_search | 20 条，每条摘录 160 字 |
| map_get body | 500 字 |

禁止返回坐标大数组、全量 sibling。

工具：`map_get` / `map_search` / `map_overview` 只读。无 add/link/move/hide。

## 12. 包形态

> **落地修正（2026-09-27，主人拍板「改规格，不改实现」）**：本节原写的 `.ts` 文件名与目录划分
> 与实际实现不符。**以本节下方的新版为准**，实现不动。三条修正：
>
> 1. **包内全是 `.js`**，没有 TypeScript、没有构建步骤。原因见 §6 约束：宿主 runtime 解析不到裸包名，
>    客户端 bundle 又必须是单文件自包含普通脚本 —— 引入 TS 只会多一层构建负担而无收益。
> 2. **`src/overlay/` 拆成 8 个模块**（原写"落链、补链、上提、防环、patch"过于笼统）。
> 3. **画布未做**：`src/client/` 目前**没有画布**，只有链式列表 + 行内操作按钮。
>    画布计划见 [`04-画布计划.md`](04-画布计划.md)。
