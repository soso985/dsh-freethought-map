# 画布计划（Canvas Plan）

> 目标：把已经写好但**没有 UI** 的能力接出来，让这个插件从"能看"变成"能用"。
>
> 本文对账的两边：
> - **原型**（`E:\FreeThought Map`，React Flow 版 v0.1）—— 交互已经跑通，是参照物
> - **本包**（`dsh-freethought-map`）—— overlay 数据模型与全部纯函数已就位，缺画布
>
> 结论先行：**画布不是"再加一个功能"，而是把 5 个已实现的操作从死代码变成入口。**

### 1.2 本包目前**唯一**的界面（`src/client/index.js`，1104 行）

实测：面板里**一共 8 个可点元素** ——

```
链行（2 个：行本身 / 「跳到气泡」）· 导出 JSON · 导出 MD · 导入 · 重建投影 · 帮助 · 收起
```

**没有的**：拖动、手建、改父、摘除、注解输入、拉线、Ctrl+Z、框选、缩放、右键菜单。

也就是说：**卡 7 那 635 行 `undo.js` 是死代码** —— 断言全绿，但用户点不到。

### 1.3 原型的交互清单（`src/components/Canvas/Canvas.tsx`，368 行）

这些是**已经跑通、值得照抄**的行为，逐条列出以免遗漏：

| 交互 | 原型实现 | 本包能否直接搬 |

| **点线即断** | 粉线→删联想；灰线→`setParent(target,null)` | ✅ 有 `removeFreeLink` / `opSetParent` |
| 右键菜单：新建子/同级、锁定位置、删除 | 4 项 | ✅ 手建/删都有；锁定是几何字段 |
| 方向键平移画布（打字时让位） | `ArrowKeys` + `panBy` | ✅ 纯视口 |
| `fitView` 只在**首次挂载**与**显式信号**时 | `fitSignal` + 60ms 延迟 | ✅ 规格 §5 也要求"不整图 fit" |
| 网格背景、缩放 0.1–2、`Controls` | `<Background>` `<Controls>` | ⚠️ 要自己画 |
| 搜索命中高亮（**绝不移动节点**） | `matched` Set | ✅ 有 `map_search` 的同款逻辑 |

**原型刻意不做的**（照抄这个"不做"列表）：自动成树、自动整理、模型改图。

## 2. 硬约束（决定方案只能怎么选）

| 约束 | 证据 | 后果 |
| --- | --- | --- |
| 客户端 bundle **不能 `import` / `export`**，必须单文件自包含 | 卡 0/1 实证：`export` 会 `SyntaxError`，插件静默死；`verify-package` 有断言 | **不能直接用 `@xyflow/react`** |
| 宿主 runtime **解析不到任何裸包名** | `docs/HOST.md` §3.9 | 不能 `require('zustand')` 等 |
| React 只能从宿主模块表取 | 官方 skill 要求 | 已有；但**没有构建步骤** |
| 不能替换 app root / 不能往 `document.body` 追加 | 官方 skill 要求 | 画布只能在**自己的面板内**渲染 |

> 原型靠 `@xyflow/react` + `html-to-image` + `zustand` + Vite 构建。这四样在本包里
> **一样都不能直接用**。这是画布工作量的真正来源 —— 不是"写个画布"，而是
> "在没有依赖、没有构建的情况下，把画布的必需品自己实现一遍"。

## 3. 三条可选路线

### 方案 A：零依赖手搓 2D 画布

在面板内用 `position:absolute` 放节点、`<svg>` 画线。

- ✅ 不引入任何依赖，不需要构建步骤，符合全部约束
- ✅ PNG 导出可用 `<canvas>` 2D 自绘（不依赖 `html-to-image`）
- ❌ 工作量大：平移/缩放/框选/命中测试/贝塞尔避让都要自己写
- ❌ 最容易出问题的是**命中测试**（点线断开、锚点拉线），而这类"手感"问题**无法离线验证**

**规模估计**：约 700–1000 行客户端代码 + 约 200 行纯几何函数（可离线测）。

### 方案 B：先做「列表 + 结构编辑」，不碰 2D

保持现在的链式列表，把**操作**接上去：行内编辑注解、行上删按钮（走 `opDelete` 上提）、
"＋"新建子节点、`Ctrl+Z` / `Ctrl+Shift+Z`。

- ✅ 工作量小（约 250–350 行），能**立刻**让 635 行 `undo.js` 活过来
- ✅ 全部可离线验死 + 真浏览器可验（点击/键盘，不依赖手感）
- ❌ 失去"空间感"—— 节点的 `position`/`width`/`height` 仍然用不上，仍是"一维链"

**规模估计**：约 250–350 行，其中约 120 行纯函数。

### 方案 C：B 之后再做 A

先 B 让插件可用，再 A 补空间画布，两者共用同一套 overlay 与撤销栈（A 只是换个渲染面）。

- ✅ 每一步都有可验收的产出；风险被切小
- ✅ B 期间会暴露"接线层"的真实需求（并发保存、撤销与投影交错），A 直接受益
- ❌ 总工作量最大；中间态需要一次界面重构

---

## 4. 建议路线：C（先 B 再 A），理由

1. **B 立刻消除"死代码"**：卡 7 的逻辑已经写完并有 40 条断言，接个 UI 就能用。
   这一步的性价比最高，且**不需要任何新设计决策**。
2. **B 验证"接线层"**：撤销栈与 `save` 的并发、`Ctrl+Z` 与官方输入框的焦点冲突、
   `HistoryBySession` 的归属（见 §5 待定项 1）—— 这些问题在 A 里同样存在，
   但 B 的验证成本低得多。
3. **A 的不可验部分被推到最后**：命中测试、拖拽手感只能靠真机试。
   把可离线验证的部分（几何纯函数）在 A 之前写好，真机阶段就只剩"接线对不对"。

**如果只能做一件事**：做 B。它用最小代价把插件从"能看"变成"能用"。

## 5. 待定项（需要主人拍板，不擅自决定）

| # | 问题 | 选项 | 影响 |
| --- | --- | --- | --- |
| 1 | **撤销栈放在宿主还是客户端？** | (a) 宿主一份、随会话（跨刷新仍在进程内）<br>(b) 客户端一份（刷新即丢，与规格 §7「第一版允许只活在内存」一致） | 规格说"刷新后可丢"，两者都合规；但 (a) 在切标签页后仍可撤销，(b) 更简单 |
| 2 | **`Ctrl+Z` 的作用域** | (a) 只在面板内获得焦点时生效<br>(b) 全局面板开着就生效 | 官方输入框里也有撤销。全拦截会破坏宿主体验 —— 卡 1 的键盘隔离已断言"面板内 Ctrl+Alt+M 不外泄"，倾向 (a) |
| 3 | **要不要做框选/多选** | (a) 第一版只做单选<br>(b) 一开始就多选 | 多选会牵动 `selectedIds` 的权威归属（目前 overlay 里**没有** selectedIds 字段） |
| 4 | **PNG 导出** | (a) 画布做完再做（`<canvas>` 自绘）<br>(b) 一直不做 | 目前 `exportDoc('png')` **明确拒绝**并说明原因，没有导出假图 |
| 5 | **`selectedIds` 算视图状态还是 overlay 字段？** | (a) 视图状态（**原型就是这么做的**：`MapDoc` 里只有 `nodes`/`freeLinks`/`updatedAt`，没有 `selectedIds`）<br>(b) 落盘进 overlay | 规格 §6 把 `selectedIds` 列在 overlay 字段里，但**实现与原型都没有落盘它**。这是一处"规格 vs 实现"的不一致，需要修正其中一边 |

> 第 5 条已核实：本包的 `createOverlay` 落盘的是
> `version / sessionId / rev / nodes / freeLinks / focusId / hidden / updatedAt` —— **没有 `selectedIds`**。
> 原型的 `MapDoc` 是 `version / nodes / freeLinks / updatedAt` —— 也没有。
> 所以两边都把"选中"当视图状态。建议**改规格**而不是改实现（选中态跨设备/跨刷新恢复没有价值，
> 反而会让"点空白清选中"变成一次写盘）。

## 6. 分阶段计划

### 阶段 1（= 方案 B）· 让结构编辑真正可用

**做：**

1. 行内编辑注解（双击/回车提交，`opAnnotate`；**空串是合法值**，要有"清空"语义）
2. 每行「＋ 新建子节点」（`opCreateManual`，父 = 该行；防环已经由 `canSetParent` 守住）
3. 每行「摘除」（`opDelete`；子节点上提、粉线删、turn 写 hidden、焦点回退）
4. `Ctrl+Z` / `Ctrl+Shift+Z` 接 `HistoryBySession`（**只记用户操作**，投影绝不进栈）
5. 焦点迁移（已做）+ 把 `focusId` 的写回统一走 `save`

**验收：**

| 验收条 | 怎么验 |
| --- | --- |
| 写注解后落盘，`""` 显示空而**不回退**派生标题 | RPC 读回 + 真浏览器看文本 |
| 摘除后对话还在、子节点上提、撤销能完整恢复 | 纯函数断言（已有 40 条）+ 真浏览器点一次 |
| 撤销拖动**不删**投影节点 | 已有断言（"拖动期间到达的 AI 投影"） |
| `Ctrl+Z` 只在面板内生效，不抢官方输入框 | 真浏览器：焦点在面板内 vs 在官方输入框，各按一次 |
| 切会话换栈 | 已有断言（会话隔离） |
| 刷新后不可 Ctrl+Z（帮助里已写明） | 真浏览器：刷新后按 Ctrl+Z 应当无效且不报错 |

**风险：** 低。全部是已有纯函数的接线。

### 阶段 2（= 方案 A 的可验部分）· 先写几何纯函数

在碰 DOM 之前，先把能离线测的算清楚，**新增 `src/overlay/geometry.js`**：

- `clientToWorld` / `worldToClient`（含 pan/zoom）
- `hitTestNode(point, nodes)`（含 z 序：后画的在上）
- `hitTestEdge(point, edges, tolerance)`（点到贝塞尔的最近距离）
- `rectIntersectsNode(rect, node)`（框选）
- `edgeAnchorSides(fromRect, toRect)`（照抄原型 `AutoTreeEdge` 的"实时算进出边"思路：
  写死 'b'/'t' 会让子节点跑到父节点上方时绕远路 —— 原型注释里说明了这个坑）
- `planReveal` 已有（规格 §5「轻推视口、不整图 fit」）

**验收：** 每条 ≥3 个断言（含边界：点正好在边上、缩放下、节点重叠时谁在上）。

**风险：** 低。纯函数。

### 阶段 3 · 2D 画布（不可离线验证的部分）

- 节点盒：绝对定位 + 拖动（拖动期间**只改内存**，松手才 `save` 一次）
- 平移/缩放：右键拖平移 + 滚轮缩放（0.1–2，照抄原型），**方向键平移**
- 画线：Tree 灰实线 + 箭头；粉线粉色虚线
- **拉线**：下边锚点→改父；左右锚点→粉线
- **点线即断**：粉线→删；灰线→置顶层
- 右键菜单：新建子/同级、锁定位置、摘除
- 网格背景
- 焦点/选中视觉分离（规格 §5）

**验收：** 只能真浏览器（CDP）驱动。**必须记录到 `docs/HOST.md`：哪些是实测、哪些没测。**

**风险：** 高。这是唯一"手感"决定成败的部分，且反复迭代成本高。

### 阶段 4 · PNG 导出

`<canvas>` 2D 自绘（节点矩形 + 文字 + 线），不引入 `html-to-image`。
在那之前 `exportDoc('png')` 继续**明确拒绝**，不导出空图。

## 8. 建议的最小第一步

**只做阶段 1 的第 1 项：行内编辑注解。**

理由：它是"用户能表达自己想法"的最小闭环，成本最低（约 40 行），
且能立刻验证整条链路（UI → `opAnnotate` → `save` → 落盘 → 刷新后仍在）。
做完这一项，再决定要不要一次把阶段 1 做完。
